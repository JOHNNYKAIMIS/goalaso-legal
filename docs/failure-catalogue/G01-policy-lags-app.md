# G01 — Η πολιτική μένει πίσω από την εφαρμογή

## Το περιστατικό (μετρημένο 2026-08-21 από το git)

Η πολιτική απορρήτου περιέγραφε διαγραφή λογαριασμού «μόνο μέσω email» ενώ η εφαρμογή είχε
αποκτήσει in-app διαγραφή. Διορθώθηκε **με το χέρι**, όταν το πρόσεξε κάποιος:

```bash
git log --format='%h %ad %s' --date=short
# 30421cc 2026-08-03 Privacy policy: in-app account deletion now exists (was email-only interim)
```

Δεύτερο στιγμιότυπο, ίδια μέρα: προσωπικό όνομα/email στην πρώτη έκδοση, αφαιρέθηκε σε δύο
διορθωτικά commits — πάλι με το μάτι, όχι με μηχανισμό.

## Το περιστατικό ΞΑΝΑΣΥΝΕΒΗ (μετρημένο 2026-08-22 στον κώδικα της εφαρμογής, `goalaso` @ `c7bdb6b`)

Δεκαπέντε μέρες μετά τη διόρθωση, η εφαρμογή άλλαξε ξανά και η πολιτική όχι:

```bash
# στο repo της εφαρμογής (Documents/goalaso):
ls supabase/migrations | grep first_last      # 20260818000032_first_last_name.sql — όνομα + επώνυμο στον users
grep -rlE 'first_name|firstName' apps/mobile/src | wc -l    # 9 αρχεία (sign-in.tsx, edit-profile.tsx: «Όνομα»)
grep -n 'display_name\|Display name' ../goalaso-legal/privacy.html   # η πολιτική λέει ΜΟΝΟ «όνομα εμφάνισης»
```

Και τρία ακόμα πράγματα που η εφαρμογή κάνει και η πολιτική δεν λέει (ΚΕΝΑ):

```bash
grep -rn "from('crash_reports')" backend/src      # crashStore.js — αναφορές σφαλμάτων (app_version, platform, stack, context)
grep -rn "from('waitlist_emails')" backend/src    # waitlistRepo.js — email καλεσμένων ΧΩΡΙΣ λογαριασμό (λίστα αναμονής)
grep -n 'region' render.yaml                      # region: frankfurt — ο API server τρέχει σε Render, όχι μόνο Supabase
grep -n '"url"' apps/mobile/app.json              # https://u.expo.dev/… — OTA updates μέσω Expo (τρίτος)
```

Ό,τι η πολιτική **λέει** αρνητικά, ισχύει (μετρήθηκε 0 SDK κάμερας/gallery, GPS, πληρωμών,
διαφημίσεων· `avatar_url` ανενεργό· `analytics_events` και `device_tokens` πίνακες χωρίς κανέναν
που να τους γράφει). Ό,τι **δεν λέει**, είναι το πρόβλημα.

## Γιατί ξαναγυρίζει

Η σελίδα ισχυρίζεται πράγματα για την ΕΦΑΡΜΟΓΗ (in-app διαγραφή, hashed tokens, Φρανκφούρτη,
καμία διαφήμιση, καμία πληρωμή) — αλλά ζει σε άλλο repo από αυτήν. Κάθε αλλαγή της εφαρμογής
που αγγίζει δεδομένα μπορεί να καταστήσει την πολιτική αναληθή **χωρίς κανένα σήμα εδώ**. Και μια
αναληθής πολιτική απορρήτου δεν είναι τυπογραφικό — είναι ψευδής δήλωση προς χρήστες και
εποπτική αρχή.

## Τι το κλείνει μόνιμα

Κατάλογος «ελέγξιμων ισχυρισμών» (ένας πίνακας: ισχυρισμός → πώς επαληθεύεται στην εφαρμογή) και
βήμα στο release checklist της εφαρμογής που τον διατρέχει. Πλήρες κλείσιμο = ο φύλακας ζει στο
repo ΤΗΣ ΕΦΑΡΜΟΓΗΣ και κοκκινίζει όταν αλλάζει κώδικας που αγγίζει κατηγορία δεδομένων χωρίς
να αγγιχτεί η πολιτική.

**Τι ΔΕΝ φυλάει (ρητά):** ισχυρισμούς διαδικασίας (απάντηση σε 30 ημέρες, παιδιά <18) — μόνο
άνθρωπος· την περιοχή του **live** Supabase project (τα έγγραφα λένε eu-central-1, δεν μετρήθηκε
στο dashboard)· και, από αυτό το repo, το ίδιο το γεγονός ότι η εφαρμογή άλλαξε — αυτό το πιάνει
μόνο το `--app` στο CI της εφαρμογής (απόφαση ιδιοκτήτη). Μέχρι τότε: η λήξη των 60 ημερών είναι
το μόνο ρολόι.

# G03 — Χειρόγραφη ημερομηνία «Τελευταία ενημέρωση»

## Το περιστατικό (μετρημένο 2026-08-21)

Το privacy.html υπόσχεται: «Αν αλλάξει ουσιωδώς αυτή η πολιτική, θα ενημερωθεί η ημερομηνία στην
κορυφή». Η ημερομηνία αυτή είναι το ΜΟΝΟ σήμα αλλαγής προς τον χρήστη — και συντηρείται με το
χέρι. Ήταν λάθος **από την πρώτη μέρα**:

```bash
grep -n "Τελευταία ενημέρωση" privacy.html          # «4 Αυγούστου 2026»
git log --date=iso -S"4 Αυγούστου" --format='%ad'    # commit: 2026-08-03 19:23 — μία μέρα ΠΡΙΝ
# Επαληθεύτηκε 2026-08-22 σε clone: 30421cc 2026-08-03 19:23:26 +0300. Τα 3 προηγούμενα commits
# (9b6aa96, 843f99b, 9bfa4b6) έγραφαν «3 Αυγούστου» — η αλλαγή σε «4» έγινε ΜΟΝΟ στο 30421cc.
```

Η σελίδα δηλώνει ενημέρωση σε ημερομηνία κατά την οποία (σύμφωνα με το git) δεν άλλαξε τίποτα.

## Γιατί ξαναγυρίζει

Χειρόγραφη ημερομηνία = υπόσχεση χωρίς μηχανισμό. Η επόμενη ουσιώδης αλλαγή είτε θα ξεχάσει την
ημερομηνία (χειρότερο: ο χρήστης δεν μαθαίνει ποτέ ότι άλλαξε η πολιτική), είτε θα τη γράψει
λάθος — όπως ήδη έγινε.

## Τι το κλείνει μόνιμα

Φύλακας σε CI: η ημερομηνία της σελίδας οφείλει να ισούται με την ημερομηνία του τελευταίου
commit που άγγιξε το αρχείο (με γραπτή εξαίρεση για commits που δηλώνονται μη-ουσιώδη, π.χ.
`[no-date]` στο μήνυμα). Ελέγχει και τη συμφωνία EL ↔ EN της ίδιας ημερομηνίας (βλ. G02).

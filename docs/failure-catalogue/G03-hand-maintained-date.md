# G03 — Χειρόγραφη ημερομηνία «Τελευταία ενημέρωση»

## Το περιστατικό (μετρημένο 2026-08-21)

Το privacy.html υπόσχεται: «Αν αλλάξει ουσιωδώς αυτή η πολιτική, θα ενημερωθεί η ημερομηνία στην
κορυφή». Η ημερομηνία αυτή είναι το ΜΟΝΟ σήμα αλλαγής προς τον χρήστη — και συντηρείται με το
χέρι. Ήταν λάθος **από την πρώτη μέρα**:

```bash
grep -n "Τελευταία ενημέρωση" privacy.html          # «4 Αυγούστου 2026»
git log --date=iso -S"4 Αυγούστου" --format='%ad'    # commit: 2026-08-03 19:23 — μία μέρα ΠΡΙΝ
# Επαληθεύτηκε 2026-08-22 σε clone: 30421cc 2026-08-03 19:23:26 +0300. Τα 3 προηγούμενα commits
# (9b6aa96, 843f99b, 9bfa4b6) έγραφαν «3 Αυγούστου» — η αλλαγή σε «4» έγινε ΜΟΝΟ στο 30421cc.
```

Η σελίδα δηλώνει ενημέρωση σε ημερομηνία κατά την οποία (σύμφωνα με το git) δεν άλλαξε τίποτα.

## Γιατί ξαναγυρίζει

Χειρόγραφη ημερομηνία = υπόσχεση χωρίς μηχανισμό. Η επόμενη ουσιώδης αλλαγή είτε θα ξεχάσει την
ημερομηνία (χειρότερο: ο χρήστης δεν μαθαίνει ποτέ ότι άλλαξε η πολιτική), είτε θα τη γράψει
λάθος — όπως ήδη έγινε.

## Τι το κλείνει μόνιμα

Φύλακας σε CI: η ημερομηνία της σελίδας οφείλει να ισούται με την ημερομηνία του τελευταίου
commit που άγγιξε το αρχείο (με γραπτή εξαίρεση για commits που δηλώνονται μη-ουσιώδη, π.χ.
`[no-date]` στο μήνυμα). Ελέγχει και τη συμφωνία EL ↔ EN της ίδιας ημερομηνίας (βλ. G02).

## Ο φύλακας (γύρος 2 — 2026-08-22)

| | |
|---|---|
| Φύλακας | `node scripts/date-check.mjs [φάκελος]` — για κάθε σελίδα με «Τελευταία ενημέρωση: D Μήνας YYYY»: η ημερομηνία = `git log --format=%cs -- <αρχείο>` του **τελευταίου ουσιώδους** commit (commits με `[no-date]` στο θέμα αγνοούνται). Η συμφωνία EL ↔ EN της ημερομηνίας ελέγχεται από τον φύλακα G02 |
| Απόδειξη | `node scripts/date-prove.mjs` — προσωρινά git repos με commits σε ελεγχόμενες ημερομηνίες (`GIT_COMMITTER_DATE`): σελίδα ≠ commit → κόκκινο (το περιστατικό)· ουσιώδες commit χωρίς ενημέρωση ημερομηνίας → κόκκινο· `[no-date]` αγνοείται· untracked αρχείο → κόκκινο· όχι git / ρηχό clone / 0 σελίδες με ημερομηνία → exit 2· + το πραγματικό repo → πράσινο |
| Γνωστό χρέος | [`docs/known-debt.json`](../known-debt.json) → `date`: privacy.html σελίδα 2026-08-04 / commit 2026-08-03, λόγος + λήξη **2026-09-21**. Η εγγραφή ισχύει ΜΟΝΟ αν ταιριάζει ακριβώς (ίδια σελίδα ΚΑΙ ίδιο commit) — αν κάποιος αγγίξει το αρχείο ή αλλάξει την ημερομηνία, γίνεται ΝΕΚΡΗ και ο φύλακας πέφτει: η απόφαση ξαναμπαίνει μπροστά σου |
| Πού τρέχει | `.github/workflows/quality.yml` με `fetch-depth: 0` — ρηχό clone = exit 2, όχι πράσινο |
| Λογοδοσία | «✓ date:check — 2 σελίδες με ημερομηνία (privacy.html, terms.html), 1 χωρίς (index.html), 1/2 = τελευταίο ουσιώδες commit (+1 γνωστό χρέος: privacy.html 2026-08-04 ≠ 2026-08-03, λήγει 2026-09-21), 0 [no-date] commits αγνοήθηκαν» |
| Fail-closed | όχι git repo, ρηχό clone, 0 σελίδες με ημερομηνία → exit 2 |

**Αναπαραγωγή (2026-08-22):** χωρίς το known-debt.json ο φύλακας είναι ΚΟΚΚΙΝΟΣ στον σημερινό
κώδικα: `privacy.html:20: ημερομηνία σελίδας 2026-08-04 («4 Αυγούστου 2026») ≠ τελευταίο ουσιώδες
commit 30421cc 2026-08-03`. Το terms.html (3 Αυγούστου = `9bfa4b6 2026-08-03`) είναι σωστό.

**Η σύμβαση από εδώ και πέρα:** κάθε commit που αγγίζει σελίδα με ημερομηνία είτε ενημερώνει την
ημερομηνία στη μέρα του commit (ουσιώδης αλλαγή — ο χρήστης πρέπει να το μάθει), είτε φέρει
`[no-date]` στο θέμα (τυπογραφικό, markup, `lang`). Δεν υπάρχει τρίτη επιλογή — ο φύλακας πέφτει.

**Δρόμος κλεισίματος του χρέους (απόφαση ιδιοκτήτη):** commit `[no-date] privacy: ημερομηνία 3
Αυγούστου 2026` (και «August 3, 2026») + αφαίρεση της εγγραφής από το known-debt.json. Τότε το
τελευταίο ουσιώδες commit παραμένει το `30421cc` (2026-08-03) και η σελίδα λέει αλήθεια.
